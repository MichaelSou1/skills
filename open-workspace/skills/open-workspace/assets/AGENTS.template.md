## 1. 执行位置与接手

本机负责主要代码、文档、配置编辑与 GitHub 管理。在用户授权的范围内自主完成可逆开发、检查与修复，不因修改行数增加人工门槛。
没有指定服务器时，根据用户要求和本机资源执行；指定服务器时按下方分工执行。同一分支或共享 checkout 同时只指定一个写入端。
每次开工、接手、上下文恢复或重启代理，先读用户最新要求、主计划、状态、交接与最近失败记录，核对依赖、预算和停止条件。
核对代码 commit 和未提交修改；接管作业时检查进程、日志、checkpoint、数据游标与累计成本，不能只凭聊天或旧记录推断状态。
分清已完成、仍运行、尚未开始与证据不足；涉及“当前、最近、最新”等判断时，核对会话日期并现场检查或联网核实，注明时间与时区。

## 2. 存储、环境与大产物

项目运行时根为 `{{runtime_root}}`，集中存放 `envs/`、`cache/`、`datasets/`、`models/`、`runs/`、`logs/`、`tmp/` 与 `secrets/`。
所有项目安装、缓存、临时文件和下载分片写入允许目录；不写他人目录、系统 Python、系统驱动目录或未经允许的根盘位置。
环境入口建议为 `scripts/project_env.sh`；这是待实施约定，只有文件实际创建并验收后，才要求每个项目进程先 source 它。
环境入口应明确项目 Python 与缓存目录，核查工具默认的 `/tmp`、用户缓存及注册文件；不修改 `HOME`，项目 Python 缺失时不能默默用系统 Python 运行实验。
**本项目必须使用 conda 管理环境依赖**，在项目运行时根的 `envs/` 下创建隔离 conda prefix；不得以 venv、uv 环境或系统 Python 替代。确有需要时可在该 conda 环境内使用 pip 补充依赖，但仍须由同一项目 conda Python 执行。
明确记录 conda prefix 与项目 Python 的绝对路径，成套锁定 Python、框架、wheel 和 kernel 依赖；环境尚未创建时注明待建立，不因写入本约定就自动安装环境。
将 `CONDARC`、`CONDA_PKGS_DIRS`、`CONDA_ENVS_PATH` 与安装缓存导向允许目录，核查用户环境注册；多进程及 worker 核对实际 conda Python，避免继承其他项目的 site-packages。
下载前核对空间、网络与版本，优先断点续传，记录 revision、清单、数量、字节数和必要校验；不把代理地址或凭据写死进仓库。
代码、配置、锁文件、manifest、小型指标、预测、失败分析与成本记录入 Git；模型、原始大数据、checkpoint、大日志和完整批量轨迹留在运行时根。
manifest 关联来源、精确版本、生成 commit、命令、产物位置与恢复方法，不能因产物被 ignore 就丢弃实验记录。
清理唯一大产物前先完成可恢复备份并核对数量、字节与必要校验，记录保留策略和 `BACKED_UP.md`；不复用其他项目的备份账号或目录。

## 3. Git、同步与凭据

开始修改前确认 branch 与 working tree，并 `git fetch origin`；提交、推送前再次核对远端变化，只做可确认的快进同步。
出现分叉或另一端未提交修改时保存 diff 并消解，不强推，不用 `reset --hard`、`clean -fd` 丢弃未审阅修改。
共享 checkout 只指定一个 Git 写入端；worker 使用代码期间不并发 pull、checkout 或 commit。每次实验固定 commit，多个版本使用隔离 checkout。
如需执行未提交代码，先保存可重建补丁与配置快照；不得声称实际执行代码已由 commit 完全固定。
新增 GitHub 仓库默认私有；复用已有仓库时核对 owner、URL 与权限，不擅自改变已有仓库可见性或 origin。
本机使用 `gh` 管理 GitHub，账号认证与仓库凭据均不得入 Git。
私钥、`.env`、API key、代理凭据和私有 SSH 配置不入 Git、不进日志；不以 `set -x`、`env` 或请求 headers 输出秘密。
<!-- BEGIN REMOTE -->
服务器仅使用本仓库独立的读写 deploy key 进行 Git 传输，不能复制本机 `gh` token 或复用其他仓库私钥。
deploy key 不授予 GitHub API 或账号权限。只记录 key_id、公钥 fingerprint 与配置路径，不记录私钥内容。
服务器 Git 传输使用项目局部 SSH 配置及经验证的 known_hosts；不覆盖全局 SSH/Git，不设置 `StrictHostKeyChecking=no`。
服务器提交使用可识别的项目 Git identity；本次授权和凭据连通性通过核验后才能 push，历史测试不能代替本次检查。
<!-- END REMOTE -->
无法直连时可用已核验的 Git 通道或经 SSH 传输 git bundle，在允许目录落盘并校验快进关系；不能强制重置掩盖分叉。
同步完成核对本机 HEAD、GitHub 主分支 ref 与服务器 HEAD；未配置服务器时只核对两端。分别报告 working tree 状态和未同步内容。

## 5. 实验协议与证据

按用户目标和原论文制定计划，明确复现与适配的差别；冻结模型、数据、方法、指标、评测协议、预算、验收及停止条件后再运行。
不把创建工作区或编写计划视为数据下载、教师额度、长时训练、付费 API 或另开聊天的授权；后续动作依据用户已明确的范围推进。
先验证数据和评分语义、接口、最小连续执行及恢复，再扩量；需要训练时检查更新、checkpoint、重载与评测切换，而非只看程序退出码。
模型、数据和工具锁定精确 revision；训练、验证、测试划分及污染控制按任务制定，测试集不能用于调参、筛选、合成或教师生成。
同一研究对照保持模型起点、有效数据/token、生成和计算预算可比；多项同时变化时说明无法单独归因的范围。
保留任务/样本 ID、split、seed、代码/数据/模型/评分版本、逐样本结果及排除原因；私有标签、隐藏测试和评测真值隔离于模型可见输入。
使用模型 API 时记录版本、prompt、缓存、重试与用量，不记录密钥；缺失或 UNKNOWN 单列，不能伪造或填 0 代替未测结果。
区分论文报告、社区描述、现场测量与推测；loss 下降、权重变化、单次涨分或工程跑通不能证明方法有效，结论依据匹配对照和适当的不确定性。

## 6. 子代理协作

可以独立交付和验收的工作包由主代理派发子代理；主代理负责调度、验收、综合与汇报，原子任务负责人不为形式递归拆分。
派发写清目标、输入、依赖、可编辑文件、执行位置、预算、验收与返回内容；无文件/资源争用可并行，不能为并行越过依赖。
同一文件只指定一个编辑负责人；主代理维护卡号、端口、运行目录、checkout 和 API 配额。工作包 ID 与实验 run_id 分开并关联。
返回做了什么、产物、证据、限制、活动作业、成本与下一步；不能直接把子代理返回等同实验成功。
失联先查进程和产物，再交接目标、diff、日志、checkpoint、错误、剩余预算及恢复方法；正常作业接管观察，不重复提交。
平台不支持或暂时无法派发时记录限制，在授权范围内继续独立工作；不能虚称已委派或已完成。

## 7. 实验账本与恢复

首次开展实验时建立 `docs/experiments/index.md`、`status.md` 与 `records/<run_id>.md`；它们是约定入口，未创建前不能声称已有账本。
机器可读版本、资源与配置放 `manifests/experiments/`，小型结果放 `results/experiments/`，大产物放运行时根的 `runs/<run_id>/`；既有证据用链接关联，不移动活动作业。
每次运行记录 run_id、parent_run_id、attempt_id、状态与带时区时间；以下八项必填，未知或不适用明确说明：

1. 目的、假设、阶段、协议与预先定义的继续/停止判据。
2. 对照 run_id、唯一改动和保持项；多项变化的归因限制。
3. 数据、模型、参数、工具、奖励/评分、split 与精确版本。
4. seed、commit/补丁、环境锁、Python、节点/GPU、资源快照、命令、PID、日志、游标与恢复 checkpoint。
5. 核心指标、分母、差值、不确定性、逐样本证据，以及 GPUh、墙钟、CPU 与 API 成本；失败也记成本。
6. 是否符合启动前预期，区分符合、不符合与证据不足。
7. 证据支持的结论、混杂、负结果与 pass / revise / stop / inconclusive 决定。
8. 下一动作、负责人、依赖、验收、剩余预算与停止理由。

启动前写计划不填结果；运行中及时记录关键事件；结束或失败后同步索引、状态与主计划，未通过验收不能勾完成。
修订/重试保留旧记录并建立 parent_run_id；同协议续跑可沿用 run_id，但另记 attempt_id、恢复位置与累计成本，重启不能清零预算。
异常先保存命令、规模、版本、完整错误与现场，隐藏凭据；查官方源码、文档、发布说明、论文与 issue，记录链接、日期和版本差异。
根据最可能原因做最小可逆验证再修复，检查研究语义和必要基线；不擅自换用户指定的框架、模型或协议。
基础设施重试最多 2 次，同因重复失败须改诊断，不以换 run_id 绕过次数或预算；合理排障耗尽后说明所缺外部条件，继续不依赖它的工作。
方法无提升或假设被否定是研究结果，不是必须修到成功的工程异常；到停止条件保留证据并交付决定，不无限加跑。

## 8. 汇报与完成标准

阶段汇报使用可用的 `unpack` 技能组织表达；技能不可用时直接按“做了什么 → 观察到了什么 → 意味着什么 → 下一步”清楚说明，不因此阻塞交付。
先解释指标回答的问题，再给数字和分母；解释缩写、比较条件与限制，区分已完成、仍运行、未验证，不能以抽象措辞代替验收。
交付前核对可追溯版本、八项账本、失败和成本、剩余预算、checkpoint/恢复、产物备份、凭据与大文件隔离及活动作业身份。
工作区同步任务完成时，核对本机/GitHub/已指定服务器的同一 commit 与各端 working tree；资源检查和环境尚未验收的项单列。
交接落盘，注明下一读取位置、动作依赖、负责人、服务器是否仍有作业和剩余预算；不能预写成功或省略负结果。
