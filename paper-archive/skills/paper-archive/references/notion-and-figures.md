# Notion MCP 与原图处理

用于实际写入和配图阶段，不规定客户端或插件。工具名为官方名称示例，调用时使用当前连接实际提供的名称和 schema。

## 能力核对

官方入口：[Notion MCP supported tools](https://developers.notion.com/guides/mcp/mcp-supported-tools)。编写时于 2026-10-13 核对；后续以实时工具描述为准，文档列出的能力不等于本连接一定可用。

- 识别搜索、读取、创建／更新页面能力，通常为 `notion-search`、`notion-fetch`、`notion-create-pages`、`notion-update-page`。
- 按工具要求读取 `notion://docs/enhanced-markdown-spec`，使用支持的资源读取方式或 `notion-fetch`。其他 MCP 实现可能采用不同内容格式，不硬套标签。
- 不要求 Codex 前缀或 Notion 插件。连接只暴露部分功能时，按可用能力完成工作并说明限制。

## 目标与写入

1. 指定目标时先读取。数据库目标先读 schema，使用真实标题属性和 data source，不凭空建立字段。
2. 新归档可按论文标识符或完整标题查重，读取匹配页再判断。明确同论文同用途的笔记可补充；多个目标含义不同则问用户，不合并无关内容。
3. 未指定目标且没有明确约定位置时，在 schema 支持下使用 `creation_mode: draft` 创建私有独立页。实现必须有 parent 又不支持私有默认位置时，准备好笔记后询问目标。
4. 更新先读，优先局部修改并保留手工内容。笔记是普通页面，不标记为 Notion Skill。
5. 异步写入等待成功；有解析警告时核实影响。创建超时或结果不明时先查重／读取状态，避免重复建页。权限或能力不足时停止重复同一失败操作，交付已完成部分和缺口。
6. 回读四部分、改动和图片块；结果截断时补读相关部分，不把未读部分当作已验证。返回实际页面链接。

## 原图获取与入库

只保证 Notion MCP 可用，不能假设宿主一定有终端、Python、浏览器截图或发送 HTTP 的工具。

**优先 PDF 截图。** 有渲染／截图能力时临时读取固定版本 PDF，渲染目标页并裁出图；不上传整篇 PDF。检查图例、文字和边缘；保留原始内容与颜色，局部裁剪注明范围。

**替代为官方原图文件。** 无法截图但论文官方 HTML／项目页有同一张图时，可用核对过的原图资源，图注注明来自官方 HTML 原图。验证真实图片 URL，不猜资源编号，不拿第三方重绘冒充。

根据实际能力入库：

- 有 `notion-create-file-upload` 且客户端能发送文件时：准备上传，按返回的 URL、headers 和表单字段发送文件，再用上传响应的 `suggested_markdown` 嵌入。遵守返回限制，不把上传凭据打印到正文或日志。
- 有 `notion-create-attachment` 且来源是符合要求的公开直达图片 URL 时，可让 Notion 导入；参数和大小限制按实时 schema。
- 仅支持外部图片块时，可用稳定、公开可读的官方图片 URL，并明确是外链。不使用本地路径、登录页、PDF 链接或临时签名 URL 冒充持久图片。
- 没有可用图片入库路径时，仍完成文字笔记，对应位置保留简短图号／页码／来源链接，交付时说明图片未嵌入。不得声称“已加截图”；需要用户补充时只询问实际缺少的条件。

不要为补齐能力擅自申请令牌、部署图床或公开用户文件。图片应在回读中成为实际图片块；能预览页面时再检查显示。只验证块存在时，不声称已验证 Notion 端视觉效果。
